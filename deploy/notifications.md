# 알림 연동 및 운영

- 할 일 알림은 마감 N분 전 개별 알림(`deadlineApproaching`) 한 종류다. 09:00·18:00 정시 알림(당일 마감, D-1~3 마감 묶음, 신규 할 일 묶음)은 보내지 않는다.
- 매분 `notifyAt`(`dueDate - notificationThresholdMinutes`, 한국 로컬 시간)이 지났고 `notificationSent = false`인 미완료 항목 중 마감이 아직 지나지 않은 항목이 대상이다. 마감 시각은 한국 로컬 시간이다. 마감이 지난 항목은 발송하지 않으므로 threshold가 0이면 이 알림은 나가지 않는다.
- 마감 N분 전 알림은 사용자의 모든 기기에 발송(또는 이미 발송)된 경우에만 `notificationSent = true`로 표시한다. 일부 기기가 실패하면 다음 분에 다시 시도하고, 이미 받은 기기는 발송 슬롯으로 중복을 막는다. 알림 OFF 사용자는 표시하지 않고 건너뛴다. 발송 이후 `dueDate`가 바뀌어도 다시 발송하지 않는다.
- 마감 N분 전 알림 2분 전에 해당 사용자의 모든 기기로 기존 크롤링 신호(`action=crawl_lms`)를 한 번 보내 과제 완료 정보를 먼저 동기화한다. 매분 현재 분 기준 `(+1분, +2분]` 구간에 `notifyAt`이 있는 미발송·미완료 항목이 대상이며, threshold가 0인 항목과 알림 OFF 사용자는 제외한다. 발송 슬롯과 `notificationSent`는 건드리지 않고, 실패해도 재시도하거나 기기를 삭제하지 않는다.
- 시스템 알림 OFF이면 마감 N분 전, 게시판 알림 모두 발송하지 않는다.

## 구현

기존 `NotificationScheduler`가 실행 시점을, `NotificationService`가 대상 조회·데이터 구성과 발송을 담당한다. 기존 `taskExecutor`에서 비동기로 보내며 FCM 호출 중 DB 트랜잭션을 유지하지 않는다. 기기 하나의 실패는 로그를 남기고 나머지 발송을 계속한다.

발송 전 `(기기, 알림 종류, 기준일, 그룹 키)` 슬롯을 `notification_deliveries`에서 원자적으로 선점한다. 알림 종류는 `deadlineApproaching`, 그룹 키는 할 일 ID(`todo:{id}`), 기준일은 해당 할 일의 마감일이다. 기존 정시 알림 이력(`dueToday`, `newTodo`, `group` 키 등)은 테이블에 남아 있다. 성공한 슬롯은 다시 발송하지 않고, 실패한 슬롯은 즉시 해제한다. 처리 중 프로세스가 종료된 슬롯은 30분 뒤 다시 선점할 수 있다. 발송 완료로 표시되지 않은 항목은 매분 실행에서 마감 전까지 다시 시도된다.

게시판은 기존의 전역 최초 수신 및 제보 기기 한 대 발송 정책을 유지한다. 기존처럼 요청의 FCM 토큰을 이벤트에 전달한다. 게시판 기록이 커밋된 뒤 사용자 알림 설정과 해당 토큰의 등록 여부를 다시 확인하고, 요청 토큰으로 발송한다. 수강생 전체에게 보내는 기능은 아니다. 첫 제보자가 OFF이면 게시판은 기록하되 알림은 보내지 않는다.

게시판 제목은 기존 `title` 필드로 전달하며 표시용 알림 제목이 아니다.

## 앱 연동

기존 `sendSilentPush()`로 FCM data만 보낸다. 서버는 표시용 제목·본문과 이동 경로를 만들지 않는다. 앱이 알림 종류, 항목 수와 대표 항목 정보로 문구와 탭 이동을 결정한다. 모든 data 값은 문자열이다.

| data | 값 |
| --- | --- |
| type | deadlineApproaching / newBoard |
| count | 할 일 알림의 항목 수. 항상 1 (기존 필드 유지) |
| representative_todo_id | 알림 대상 할 일 ID. todo_id와 같음 (기존 필드 유지) |
| todo_title | 대표 할 일의 원본 제목 |
| todo_id | 단일 할 일에만 포함하는 실제 Todo ID. 기존 필드 유지 |
| todo_type | 대표 할 일의 ASSIGNMENT / QUIZ / COMMONS |
| subject_name | 대표 할 일의 과목명. 없거나 공백이면 생략 |
| due_date | 대표 할 일의 한국 로컬 마감 시각(ISO LocalDateTime) |
| action | 단일 마감 알림에만 기존 deadline_approaching 유지 |
| title | 게시판 알림에만 포함하는 기존 게시판 제목 |

앱은 `type`별로 기획된 제목·본문을 구성한다. 할 일 유형을 과제/퀴즈/강의로 표시한다. 할 일 알림은 모두 단건이므로 `count`는 항상 1이다. 과목명 누락 시 대체 문구도 앱이 정한다. 게시판에는 할 일 ID가 없으므로 홈으로 이동한다.

기존 단일 마감·게시판 식별 필드는 유지하지만 새 type 처리는 앱 수정이 필요하다. 앱은 한 메시지에 대해 새 type 처리와 기존 action 처리를 중복 실행하지 않아야 한다. 새 데이터 규약을 지원하는 앱을 먼저 배포한다.

## 운영 전제

DB 선점으로 여러 서버나 동일 작업 재호출에 의한 중복 발송을 막는다. 단, FCM이 메시지를 수락한 직후 완료 상태 저장 전에 프로세스가 종료되는 경우에는 외부 시스템과 DB를 하나의 트랜잭션으로 묶을 수 없어 재시도 시 중복될 수 있다. 실패한 알림은 마감 전까지 매분 재시도하지만 마감이 지난 알림은 소급 발송하지 않는다. FCM 수신 시각은 네트워크와 OS에 따라 지연될 수 있다.

마감 N분 전 알림 조회는 `user_todo_status(notify_at, notification_sent)` 인덱스를 사용한다. 정시 알림용으로 추가했던 `todo(due_date)`, `user_todo_status(is_completed, created_at)` 인덱스는 현재 알림 조회에 쓰이지 않는다.
